# Proposed bounded matched policy-training pilot

Status: specification only, not implemented or launched. Full training remains paused. The failed one-sided revision is excluded; the requested 1/2/5/10/15/20 head-count study is deferred.

**Question:** does the original calibrated BCA penalty improve a learned policy, beyond the frozen action-selection effect? Use the exact standalone UniFloral TD3+BC host and transferred 20k checkpoint; no CORL host/model substitution.

| Arm | Actor loss |
|---|---|
| Native TD3+BC continuation | Unchanged native loss |
| Original BCA, kappa=3 | Native loss + lambda × 3 × mean(U_original_method) |
| Actor-distance control | Native loss + lambda × 0.1 × 19.29619572569095 × mean(D) |

`D(s)=mean_over_4_action_coordinates((a_current(s)-a_frozen_20k(s))^2)`. Freeze the anchor's parameters and retain gradients through the current action. Preserve the native dataset-action BC term. Each arm computes `lambda=stop_gradient(2.5/(mean(abs(current_unpenalized_Q1))+1e-7))`. The distance definition and fixed factor match the earlier frozen selector; using the live actor and updating critics makes this a new training intervention. Distance and its gradient are zero initially because the live actor starts at the anchor; BCA need not have zero initial gradient.

Kappa=3 is a fixed exploratory choice based on positive original-BCA development gains in both batches, not an optimum or confirmed superiority. The completed one-sided pilot used kappa=1 as its original-BCA control; those settings are not conflated. Earlier locked confirmation remains inconclusive versus actor distance and will not be reused for selection.

**Matched continuation:** two paired RNG streams, three arms per stream, all starting from the identical complete checkpoint. Preserve actor/critic/target parameters, optimizer moments, normalization, phase and counters. Fork native replay/noise and auxiliary RNG streams explicitly; pair them across arms without consuming extra native randomness for penalties. Retain batch size 256, learning rates, two-critic/one-actor cadence, target smoothing, gamma=.98, horizon=100 and terminal masks. Use the same 76,800 permitted logged training rows and original 128-episode calibration bank. No evaluator/return labels enter fitting.

Two streams from one trained checkpoint measure continuation sensitivity, not independent initialization-seed replication. Evaluation and calibration reuse make this an exploratory pilot.

**Fixed budget per run:** 2,000 additional joint twin-critic optimizer updates, 1,000 actor updates, 1,000 updates of each target network and 2,000 original auxiliary updates. Six runs total: 12,000 critic, 6,000 actor, 6,000 updates of each target network and 12,000 auxiliary updates. No extension, intermediate model selection or coefficient sweep.

**Reference schedule:** bind the saved original posterior reference at the start. Refresh once after continuation critic update 1,000, using the existing two-sided native twin-min residual-scale and Bayesian/conformal mechanism. Subsequent actor updates use the new reference; the actor update at the refresh boundary uses the prior reference, consistent with existing ordering. All arms perform matching shadow auxiliary/calibration work, but controls do not use BCA widths in their actor objective. Six calibration calls total, with alpha=.1, credibility=.95 and 1,000 posterior draws each. An invalid/infinite reference causes explicit refusal, not a fallback to another penalty.

This halfway refresh is a declared pilot schedule, not an existing post-20k schedule: the current training wrapper only accepts the completed kappa=0, budget=20,000 configuration and initializes its microstep reference to None. A separate continuation adapter must bind the reference and declare the schedule; simply raising the budget is insufficient. The architecture, local fitting objective, calibration mechanism and direct-Q actor penalty stay original.

**Evaluation:** before training, reserve and hash 32 new nominal ThrusterChain reset seeds, verified unused from seed manifests without reading consumed confirmation outcomes. Use identical resets for all six final policies and the unchanged starting actor. Evaluate each policy's own action at every step, with no nine-candidate reranking. The primary metric is full-episode discounted return `sum_{t=0}^{99} 0.98^t reward_t`, preserving the established finite-horizon objective. Maximum 224 episodes / 22,400 simulator transitions. No environment interaction during offline training and no evaluation-driven fitting, stopping, strength choice or checkpoint selection.

Report paired return gains for BCA versus continued native TD3+BC, actor distance and the starting actor; show both continuation streams separately. Episode-paired intervals are descriptive and do not turn two shared-initialization streams into independent training replicates. Separately report action displacement on one fixed logged-state probe and state-trajectory displacement on paired rollouts. These distinguish policy action change from induced state occupancy change; they are not claims of OOD robustness. Deliberate environment-shift evaluation is outside this pilot.

**Advance/stop rule:** a promising exploratory result requires BCA's mean paired gain over both continued controls to exceed the existing mean numerical allowance in each stream, where each episode's allowance is `1e-6 + 1e-6*max(abs(return_BCA),abs(return_control))`. This is a numerical direction screen, not a significance test. Report all harms, intervals and shift readouts rather than selecting a favorable aggregate. Failure closes this pilot without tuning. A pass supports proposing a larger independent study; it does not automatically authorize full training or establish BCA superiority.

Abort on nonfinite updates/reference, source/checkpoint mismatch, data leakage, broken update accounting or resource limits. Preserve partial receipts, with no automatic retry. Use one local GPU, sequential runs, no package changes or paid compute. Hard wall limits: 600 seconds per training worker and 600 seconds total evaluation, at most 4,200 seconds (70 minutes), including compilation. This is a ceiling, not a runtime estimate; the previous Titan 20k run took 2,338.96 seconds and is not a Zeus throughput guarantee.
