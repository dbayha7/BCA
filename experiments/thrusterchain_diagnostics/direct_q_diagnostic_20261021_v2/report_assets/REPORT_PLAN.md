# Direct-Q diagnostic report structure

Prepared before the main V2 result bank is analyzed. No result claim is made in this skeleton. The report builder will require `results/status.json` to be complete and authenticate every recorded output hash before reading findings.

The report will distinguish three questions:

1. **Mechanical placement:** native BCA scales the behavior-cloning term; the proposed direct score subtracts a candidate-dependent width from Q1. Prior isolated tests establish the intended differentiation path, not usefulness.
2. **Frozen action ranking:** among 12 fixed candidates at each of 32 fresh designed states, does Q1 minus width choose a better one-action deviation followed by the unchanged actor?
3. **Learned policy benefit:** untested; there is no actor update, repeatedly applied new controller, or new training run here.

Required sections: fixed source→target laws; the V1 replay failure and V2 single-row numerical deployment correction; source-mapped pseudocode; pooled and support-subgroup paired decisions; candidate error/rank evidence; matched-distance and constant/detached controls; refusal/failure accounting; the tiny-stratum bootstrap limits; and all negative or unavailable findings.

The historical 95k band calibrates a one-step twin-min residual. This diagnostic scores Q1 at 100k and compares it with deterministic unsmoothed policy continuation. No true-Q coverage claim, Option C result, conditional-support certificate, or training-seed generalization will be inferred.

Only files in this `report_assets` directory are written by the reporting task. Frozen source, prepared inputs, outputs and older guides remain unchanged.
