ThrusterChain · Bayesian Conformal Aggregation on the Unifloral TD3+BC host

Does calibrated uncertainty make an offline critic choose better?

ThrusterChain is a small, fully inspectable control task: four thrusters hold five floats still against moving water, and a propeller pushed past 80% throttle stalls. A controller learned only from a fixed recording (offline reinforcement learning) must decide what to do where the recording is thin. This interface collects what the current Unifloral-based experiments have and have not shown about Bayesian Conformal Aggregation (BCA), one claim at a time, with every number traced to its report.

Five claims, kept apart

BCA subtracts a calibrated uncertainty width U from the critic's value Q1 inside the actor's objective. That is one mechanism, but it is tested against five different claims, and passing an earlier one does not establish a later one. Each row links to the evidence section that judges it.

1. Lower Q values. Subtracting κ·U lowers the score. This is arithmetic, true by construction.
See error charts
2. Error detection. Is U larger where Q1 is actually more wrong against the simulator reference? Requires a per-action association, not a lower average.
See alignment
3. Proportional correction. Does subtracting U remove overestimation without pushing values below the reference (overshoot)?
See removed versus added
4. Better action choices. On a fixed bank of candidate actions, does Q1 − κU pick higher-reference actions than raw Q1 and than simple controls? Improved and harmed switches are counted separately.
See decisions
5. Better policy returns. Does training the actor with the penalty produce a policy that earns more in the simulator, under matched data and budgets, including under controlled shifts?
See returns

Where things stand on 27 October 2026. Claim 1 holds by construction. Claims 2 and 3 are not supported on the development banks: within a state the width barely tracks the residual it is calibrated to, and that residual barely tracks the signed error against the simulator; raising the strength removes overestimation but adds underestimation. Claim 4 is not established: the penalty changes few choices, helps slightly more than it harms at strength 3, and a cheap actor-distance control does as well. Claim 5 has one positive but limited result: two continuation streams from one checkpoint beat native continuation and a distance control on 32 shared starts; the independent-seed test with a support gap did not complete on this machine. Nothing here tests an out-of-distribution start law yet.

How to read the numbers

Less negative is higher

Every return and every Q value on this page is negative, because the reward is minus a cost. A value of −30 is higher than −60. If a critic predicts −30 where the simulator reference is −60, it overestimates by 30. Every chart axis says so again.

Signed error

signed error = predicted − reference. Positive means overestimation (too optimistic), negative means underestimation. A penalty that reduces a positive error toward zero is a correction; one that drives it negative has overshot.

Three different "targets"

  • Simulator reference V. The candidate action once, then that model's own frozen actor for the remaining horizon, discount 0.98, 100 steps in total, no terminal bootstrap. It is a policy-specific value, not the optimal value Q*, and different models have different references because their actors differ.
  • Native training target y. One-step bootstrap with target networks, clipped action smoothing and the minimum of two critic heads. BCA's width is calibrated to the absolute residual between y and the twin-min critic at logged actions.
  • The earlier gamma-1 oracle. The archived 21 October pages used a 100-step undiscounted continuation on a different host. Those values are not comparable and are not shown here.

Heads are not draws

The host has two critic heads. BCA's calibration takes 1,000 Bayesian-bootstrap draws over a threshold. A head-count sweep is deferred and has no receipt.

Forced probes versus chosen actions

The decision diagnostics impose nine candidate actions at a state and ask which one each score would pick. A trained policy chooses freely. Only the policy pilots measure the second.

Strength, not count

κ ("kappa") multiplies the width. The trained checkpoint used 0; the pilots used 3; the one-sided pilot's frozen ranking used 1; the development grids swept 0.03 to 10 and selected nothing.

What this interface covers, and what it leaves out

Everything here runs on the pinned Unifloral standalone TD3+BC (repository revision f2dc127, file hash beginning 6f5ab6f9), restored and verified before every run. The repository's earlier CORL-derived host, the 100k-update checkpoints trained with it, the 21 October saved-bank Explorer, the main and weighting tests and the BCA mechanics page all belong to that earlier host. They are preserved on disk unchanged and listed under archived pages, but their results are not mixed into any chart or table here.

Nothing on this page trains, simulates or fits anything.
