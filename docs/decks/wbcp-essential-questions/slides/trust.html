Part 4 · What it adds up to

How far can the pre-registrations be trusted?

What protects the results

Expectations are written, timestamped and hashed before each run.

Their hashes are quoted in committed write-ups; the code is committed (cad0c61, 8d9ad4f).

Write-ups are audited independently; step 4's Stage 0 was fixed before any outcome.

Every number in this deck was traced to its source and re-checked.

Where it is weaker

runs/ is git-ignored, so expectation files and their timestamps are self-reported.

Many qualifiers ("partly", "mostly") are hand verdicts.

Some analyses are post hoc: critic-health thresholds, pool exclusions, the strength reanalysis.

The critic-alignment pre-registration lives only in a side worktree.

Proposed fix: commit each expectation file (or send its hash to the advisor) before its run.
