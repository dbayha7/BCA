# Real first-pair action readout, after saved-outcome acceptance

This implementation plan is written while the full saved transition join is still running and before inspecting scientific ranking or regret values. It does not authorize new science, change the original primary endpoint, or make the secondary arithmetic a pre-collection endpoint.

## Input and refusal gates

Build a separate real-data adapter in the audit workspace. Keep experiments/ood/report.py synthetic-only and all collection/accepted audit sources unchanged. Require the completed joined audit's actual exit0, the independent file-bound saved-outcome acceptance receipt, exact three-root provenance, state/candidate/key bindings and hash-bound completed rows. Refuse pending/failed acceptance, wrong source hashes, incomplete grids, aliases/conflicts, score shape mismatch, wrong collector/capture/continuation identity or extra actions. Do not load a simulator, model or weights. All report calculations use saved accepted values only.

## Original primary interpretation

For each captured state and each frozen continuation, slot0 remains the host-first-action reference. Primary harm is its raw undiscounted250-total-transition return minus each alternative return; harmful means strictly greater than1 raw reward unit. Exclude the reference slot from ranking; preserve all nine unique alternatives in this accepted zero-alias bank. Reuse the closed analyze.py definitions of ties, single-class N/A, AUROC, AP, loss rank and complete-tie-group risk retention; bind the exact analysis source hash. BCA continuation is primary, host continuation is separately labeled sensitivity/context.

Report all four collector/capture strata, their exact eligible/single-class counts and mean within-state width/support/random/constant AUROC. Report pooled AUROC separately. Compare widths with support distance and measured harm; retain the precommitted support threshold and support/harm quadrants. Show the first-action BCA-minus-host return difference within a fixed continuation, and continuation BCA-minus-host differences for the same fixed first action. No performance dashboard rebuild.

## Separately labeled secondary tested-action regret

Define finite-bank regret for slot j as max over the ten precommitted unique applied actions of the saved return minus slot j's saved return, within the same captured state and continuation. Include the reference action in that finite bank. Ties produce zero regret for every tied maximum. This is an observed tested-bank comparison, not globally optimal Q regret, not an out-of-sample selection guarantee and not a replacement for host-relative harm. It is a secondary exploratory calculation specified after collection and before this readout. Implement it separately with known-answer tests for negative returns, ties, translation invariance, invalid values and scope separation. Do not imply these maxima identify actions outside the tested bank.

Retain collector/capture/reset IDs in machine-readable exports. Do not attach five-seed confidence intervals or treat actions as independent seeds; all five declared seeds remain required. Keep fresh residual coverage and global readiness false, native width unavailable and both radius components visible. A positive global radius cannot improve action ordering.

Export exact long-form accepted observations and derived panel/stratum tables to JSON/CSV, concise Markdown/HTML explanations and standard static scientific figures. Verify plot inputs against exports and visually inspect every final figure. Clearly disclose unavailable final full-state checks and separately reconciled constructor receipt limits from acceptance. Publish only owned code, small evidence and readouts with actual push/remote/blob verification; never weights/databases/raw NPZ, thesis PDF or canonical inventory changes.
