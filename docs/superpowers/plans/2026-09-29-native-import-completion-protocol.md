# Bind the actual parent completion boundary to the unified worker

Implement the remaining concrete parent/worker protocol around the closed v4
dispatcher: bounded streaming logs, a180-second ceiling, independent Linux
identity before release and before completion acknowledgment, descriptor-checked
diagnostic readback, retained failure evidence, and source-bound os._exit with
observers retained. The parent never creates worker scratch/diagnostic roots.

The full native registration/state/cache route remains unimplemented. This work
uses explicit fixture-only paths and the exact closed fifteen-field declaration
with only fixture TMPDIR changed. It cannot enable actual production dispatch.
No closed dispatcher edit or suite rerun, installed edits, native probe, lease,
ledger, key, model or physics. No subagents, other-chat reads or messages.

1. Implement a dedicated native-import parent and worker completion protocol;
   compose it with the unchanged v4 dispatcher and ordinary saved capability.
2. Test success and failure retention with actual children, including independent
   second identity observation, malformed/missing acknowledgments, log budgets,
   timeout, source/root/diagnostic replacement, and completion without acceptance.
3. Review saved evidence in a separate stdlib process, without fixture replay.
4. Verify prior closed inputs, publish owned small evidence and code, and preserve
   the full-route hold in a guarded ACTIVE monitor update.

Completed scope:23 new fixtures cover the concrete handshake, source/spec/input
identity, environment, preexisting scratch, bounded logs, timeout and retained
worker refusals. Per-operation descriptor/name replacement checks are implemented
and reviewed in source; this suite does not independently exercise every root or
diagnostic replacement or parent-death case. Full actual-route acceptance remains
held. The closed v4 dispatcher was reused unchanged and its suite was not rerun.
